## 1. 지금 당장 해야 하는 것 하나

```
gh workflow run release.yml --ref main -f version=0.1.0 -f unreleased=true
```

**첫 태그를 밀기 전에 이걸 한 번 돌려라.** 위험은 0이다 — `publish`는 `github.event_name == "push"`일 때만 참이므로 **dispatch는 아무것도 발행할 수 없다.**

**왜 중요한가.** 라운드 4가 실행 없이 증명해서 찾은 것: 지금 상태로 태그를 밀면 `image` 잡이 이미지를 push하고 서명하고 `latest`를 옮긴 **뒤**, `artifacts` 잡이 첫 스텝에서 죽는다. `scripts/release-artifacts.sh`가 `CHANGELOG.md`에서 `## [<version>]`를 읽는데 이 리포에는 `## [Unreleased]`뿐이기 때문이다. `image`는 `artifacts`에 의존하지 않으므로(`needs: gates`), **레지스트리에 서명된 `X.Y.Z`와 옮겨진 `latest`가 남고 차트·SBOM·릴리즈가 없는 상태가 되돌릴 수 없이 만들어진다.**

그 구멍 자체는 아직 **고치지 않았다** — 라운드 4의 지시가 "증명하되 릴리즈 절차를 바꾸지 말 것"이었다. **첫 태그 전에 CHANGELOG에 실제 버전 섹션을 넣어야 한다.**

리허설이 닫지 못하는 것(첫 실제 릴리즈에서만 알 수 있음): `ghcr.io` write 권한, multi-arch 빌드, cosign keyless OIDC 왕복, `helm push`, `gh release create`, 원격 이미지 `syft scan`, 그리고 나온 서명이 제3자에게 검증되는지.

## 3. 이 리포에서 반복해서 나온 결함 부류

다음 사람이 알아야 할 가장 중요한 것. 같은 모양이 **일곱 번** 나왔다.

### 3.1 "구현됐지만 도달할 수 없다" (7회)

decide()에 HTTP 엔드포인트가 없었고, 체크포인트 서브시스템에 호출자가 없었고, 위임 MFA를 걸을 수 없었고, split 토폴로지가 `POST /decisions`를 서빙할 수 없었고, helm이 돌아올 곳 없는 콜백을 받아들였고, `CIBA.Poll`에 호출자가 없었고, **릴리즈 경로의 넷이 모든 입력에서 도달 불가능했다.**

**패턴**: 도달할 수 없는 경로는 자기 결함도 숨긴다. PKCE 누락이 데모가 브라우저 왕복을 안 돌아서 안 드러난 것이 예다.

### 3.2 "가드가 초록인데 실물이 빨갛다" (5회 이상)

`quickstart.sh`의 silent-pass 가드 넷. 콘솔 테스트가 스텁으로 서버가 안 보내는 코드를 시험. `chart_test.go`의 손으로 쓴 map이 차트와 **함께** 틀림. CI가 exit 7로 조용히 죽음. 릴리즈가 초록으로 아무것도 발행 안 함.

**그래서 이 리포의 규칙**: **모든 새 검사는 자기 검사를 갖는다.** 심어둔 드리프트에서 실제로 실패하는 것을 확인하고, **픽스처가 아니라 실물**(실제 차트 스냅샷, 실제 계약 문서, 실제 콘솔 소스)에 심어서 확인한다.

### 3.3 손으로 쓴 목록은 자기가 지키는 것과 함께 틀린다

`chart_test.go`의 역할→표면 map이 그랬다. 그래서 `mounted-routes.json`, `error-codes.json`이 **코드에서 유도**된다.

**측정된 예**: 제가 손으로 센 error 코드가 28개였는데 실제로는 **48개**였다. 네 error 테이블이 내는 18개가 호출 지점에 리터럴로 전혀 안 나타난다.

## 4. 남은 신뢰도 라운드 — 포화 시 동작

**아직 안 함.** 근거 있는 대상:

- 예산이 **인스턴스별**이다. N 레플리카가 N배를 허용한다. 문서에 적혀 있지만 부하로 측정된 적은 없다.
- 감사 버퍼가 포화에서 **드롭한다**. gap 마커가 남지만, 어느 부하에서 드롭이 시작되는지는 모른다.
- 제한기 표가 8192에서 sweep-or-refuse한다. 그 경계의 동작은 단위 테스트로만 있다.

전부 `docs/residual-review-findings/`와 각 계획서에 근거가 있다.

| 항목 | 왜 남겼나 |
|---|---|
| **check 표면이 감사 flush 간격(1초) 동안 감사 없는 allow를 낸다** — 1초 간격에서 **769–826 ms 동안 276–364개** 측정 | R32가 판정 경로 비용 때문에 비동기 버퍼를 의도적으로 골랐다. 판정마다 동기 append는 그 거래를 뒤집는다. **약속을 정확하게** 고치고 창을 테스트로 고정했다 |
| step-up 천장이 여전히 공유라 소진 가능 | **해악은 제거됐다** — 셰딩이 기록을 남기지 않는다. 남은 건 지연이고, 없애려면 분산 예산(아키텍처 결정) |
| 타이밍 부채널 (바이트는 같고 시간은 다름) | lifecycle의 모양을 바꿔야 한다. 자기 라운드가 필요 |
| 인제스트 rate 정규화가 나머지 넷과 갈라짐 | 고치면 그것에 맞춰 설정한 배포의 의미가 밑에서 바뀐다 |
| 손상된 challenge detail이 404 아닌 500 | "읽을 수 없는 detail = 대상 아님"으로 정하는 fail-closed 판단 필요 |
| `schema-read` 등 호출되지 않는 엔드포인트 5개 | `schema-read`는 **결정이 아니라 공백** — 빌더가 항상 빈 스키마에서 시작해 작성자가 무엇을 대체하는지 못 본다 |
| `delay-cancel`에 콘솔 화면 없음 | 계약에 있는 표면. 화면 만들기는 새 기능이라 최소 목표 밖 |
| 필드명(JSON 태그) 대조 | error 코드 어휘는 기계가 강제하지만 필드명은 손 검증뿐 |

## 6. 운영 메모

- **`golangci-lint`가 삭제된 sibling 워크트리 파일로 빨개질 수 있다.** `golangci-lint cache clean` 후 재실행. 실제로 이 세션에서 두 번 시간을 먹었다.
- **워크트리 base가 일관되지 않다.** `Agent`의 worktree isolation이 때로 `main`에서, 때로 현재 HEAD에서 분기한다. **워커 프롬프트에 `git reset --hard <branch>`를 명시**하는 것이 유일하게 믿을 만하다.
- **teammate로 띄운 에이전트가 결과를 자주 잃는다.** 코드 리뷰 여덟 렌즈 중 일곱이 그랬다. `run_in_background: true`인 `Agent`는 한 번도 잃지 않았다.

## 8. 이어받는 사람에게

이 리포의 검사들은 **자기가 검사임을 증명하도록** 만들어져 있다. 새 검사를 더한다면 같은 기준을 지켜라 — 심어둔 드리프트에서 실제로 실패하는 것을, **픽스처가 아니라 실물에** 심어서 확인하라.

그리고 이 세션에서 반복해서 확인된 것 하나: **재현이 안 되면 재현을 더 시도하는 대신 시스템이 말하게 만들어라.** CI의 `docker build` flakiness를 로컬에서 세 번 재현 실패했고, 진단 출력을 고치자 첫 실패에서 원인(부팅 경합)이 한 줄로 나왔다.
