# STAMP Console

A React + TypeScript (Vite) static bundle. It ships inside the engine binary via
`go:embed` and consumes **only the engine's public API** — there is no
console-specific backend (BFF) (D19).

```sh
npm ci
npm test          # type check → contract boundary check → vitest
npm run build     # tsc → vite build → bundle check
npm run dev       # dev server (the config document must be proxied from a running engine)
```

## What this shell guarantees

**The API base address comes from the server.** `/console/config.json` is the
single source. The query string, the fragment and `localStorage` are never read —
all three are channels writable by anyone who can send an approver a link, and
the console is holding that approver's token (R50). `src/config/runtime-config.ts`
is the only place that handles this value, and `scripts/check-contract.mjs`
statically rejects any code that reads it from another source.

**Everything called is inside the public contract.** Every request passes through
`src/api/client.ts`, and endpoints are addressed by **name** rather than by path.
The path templates come from `contract/public-endpoints.json`, a file generated by
`internal/api/contract.go` and compared by a Go test against the routes actually
mounted. A name that is not in the contract cannot be called, and CI checks that.

**Tokens live in memory only.** `sessionStorage` holds the PKCE verifier, the
state and the return path — nothing else, because a redirect round trip has no
other way to carry them across, and none of the three is a credential. The return
path is validated as a same-origin console path before it is written.

## Where the next units go

| Slot | Owner | What the shell already provides |
|---|---|---|
| `src/builder/` | U15 policy form builder | `/policies/*` routes, the `author` guard, `ErrorSummary`, `fieldErrorId` |
| `src/inbox/` | U16 approval inbox | `/inbox/*` routes, the `approver` guard, `Disclosure` (including R55's `onFirstExpand`) |
| `src/audit/` | U16 audit console | `/audit/*` routes, the `auditor` guard |

All three slots receive `api` (the contract-bound client), `roles` and `session`
from `useAuth()`. The shell handles 401 — screens do not implement re-login.
`renderShell({ roles, route, fetchImpl, probe })` in `src/test/harness.tsx` is the
entry point for screen tests.

## Accessibility

The shell decides it and screens inherit it (R19, R55).

- Landmarks: `banner` / `navigation` / `main#main[tabindex=-1]` / `contentinfo`, one of each
- On a route change, focus moves to `main` and an `aria-live` region announces the screen name
- The first focus target is the skip-to-content link
- The current screen is marked by `aria-current="page"` and by an underline and weight, not by colour alone
- Collapsing is visual compaction, not display suppression — collapsed content stays in the DOM
- No inline styles. The CSP is `style-src 'self'`, and the contrast values are written in `src/styles.css` alongside their ratios

`axe-core` checks the shell's screens under jsdom. The contrast rule is off there
because jsdom computes no colours; the Playwright axe pass in U15 and U16 covers
that part.
